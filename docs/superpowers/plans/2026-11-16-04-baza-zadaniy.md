# База заданий: план четвёртого этапа

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести базу до полной: пять модулей по 60 заданий, 3 кейса и около 30 карточек в каждом, каждый готовый модуль уходит пользователю обновлением базы.

**Architecture:** Программа уже умеет всё, что нужно базе. Этап состоит из одной инженерной задачи (долги третьего этапа и инструменты конвейера) и пяти одинаковых по устройству содержательных задач, по одной на модуль. Задания пишут сабагенты-авторы по темам, проверяют вслепую свежие сабагенты, детерминированные проверки живут в `tools/`.

**Tech Stack:** как в этапах 1–3 (Tauri 2, React 19, TypeScript, Vitest, Rust; `tools/` на TypeScript, zod, yaml). Сабагенты только на Opus.

**Spec:** `docs/superpowers/specs/2026-11-15-attestat-trainer-design.md` (разделы 2, 5, 6.2, 11)

## Global Constraints

- Сабагенты только с `model: opus`. Автор и проверяющий одной темы всегда разные запуски; проверяющий не видит ответов на первом этапе.
- Задания пишутся только по текстам `content/docs/<id>/text.md`. По памяти ничего не дополняется. Сторонние справочные системы запрещены; официальный скан на `publication.pravo.gov.ru` открывать можно.
- Документ с `text: ocr`: цитата только после сверки со сканом, `scan_page` обязателен, таблицы только по скану.
- Документ с `edition_status: original` и непустым `amended_by`: числа, сроки и пороги в задания не идут; норма годится, только если поправки её заведомо не затронули.
- Ловушка только в формулировке (`trap.kind: wording`). Вариантов на устаревших редакциях нет.
- Ежегодно меняющихся сумм (МРОТ, пособия) в заданиях нет.
- Весь видимый текст проходит `humanizer-ru` до слепой проверки. Нельзя менять `quote`, числа, сроки, названия актов и слова «вправе», «обязан», «не позднее», «не менее», «по согласованию», «с письменного согласия» и подобные. Длинного тире нет.
- Баланс готового модуля (раздел 5.4 проекта): 60 заданий, в каждой теме не меньше 4; `single` не больше 45%, `multiple` не меньше 30%, остальные три типа вместе не меньше 15%; сложность 20/50/30% с допуском ±10 п.п.; верный вариант самый длинный не чаще 35%; позиция верного варианта ровная.
- Кейсов 3 на модуль (в «Кадрах» один уже есть), карточек около 30 на модуль (в «Кадрах» 10 уже есть). Число кейсов в проекте не задано, это решение плана.
- Порядок модулей: кадры, ресурсы, информация, процессы, результаты.
- Пробные 25 заданий остаются в базе и входят в счёт 60.
- `id` задания никогда не переиспользуется. При содержательной правке растёт `revision`.
- Фамилии из решений комиссии не попадают в репозиторий. Сертификат Минцифры только через `curl --cacert tools/fetch/certs/bundle.pem`. VPN не трогать.
- Работа в ветке, в `main` через PR. Слияние каждого модуля и выпуск программы только после явного согласия заказчика.
- Коммиты заканчиваются `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **Модуль, по которому честных заданий меньше 60.** В «Результатах» 9 тем из 11 и в «Процессах» 8 из 12 стоят на распознанных текстах в исходной редакции. Ожидаемое поведение: модуль не объявляется готовым с натянутыми заданиями; решение о меньшем объёме принимает заказчик (Task 6 и 7, шаг 1).
2. **Два задания на одну норму с одним поворотом.** Скрипт этого не видит. Ожидаемое поведение: проверяющий модуля получает сводную таблицу «норма → задания» и отмечает дубли (шаг «Сводная проверка»).
3. **Обновление базы у человека, который уже занимался.** Правка пробного задания поднимает `revision`: прогресс по нему сбрасывается, задание приходит как новое, незаконченная сессия не ломается. Проверяется тестом на настоящей зашитой базе (Task 1).
4. **Мини-тест и «Сегодня» на модуле в 60 заданий.** Мини-тест берёт 8 заданий, а не все; сессия не превышает размер из настроек; карта тем показывает 12 тем без прокрутки по горизонтали (Task 1, дымовой тест на большой базе).
5. **Цитата из распознанного текста, оторванная от своего пункта.** В `prikaz-196` концы пунктов 22 и 42 попали в отдельные разделы. Ожидаемое поведение: разбор текста исправлен, а проверка корпуса ловит такие хвосты (Task 1).

## Структура файлов

```
tools/prompts/author-task.md      дополняется уроками пробной базы
tools/prompts/verify-task.md      дополняется сводной проверкой модуля
tools/src/blind.ts                выгрузка по теме, а не только по модулю

content/cases/<модуль>/<id>.yaml
content/cards/<модуль>.yaml

app/src/bundled/tasks.json        пересобирается перед выпуском программы
```

### Task 1: Долги третьего этапа и инструменты конвейера

**Files:** Modify `app/src/progress/ProgressView.tsx`, `app/src/training/TrainingView.tsx`, `app/src/task/TaskInputs.tsx`, `app/src/exam/ExamView.tsx`, `app/src/core/taskSchema.ts`, `app/src/bundled/tasks.test.ts`, `app/e2e/smoke.e2e.ts`, `tools/src/{blind,balance,build-tasks,validate}.ts`, `tools/fetch/pub_text.py`, `tools/prompts/*.md`, `content/topics.yaml`; Create `tools/src/{coverage,stale}.ts` и тесты

**Interfaces:**
- Produces: `npm run blind -- <модуль> [тема] --out <папка>` — файл без ответов по одной теме или модулю.
- Produces: `npm run coverage -- <модуль>` — печатает по каждой теме: сколько заданий каждого типа и сложности, сколько не хватает до раскладки, и таблицу «документ и якорь → id заданий».
- Produces: `npm run stale` — список заданий, у которых `checked` раньше, чем `fetched` документа из `refs`; код выхода 0, это предупреждение.
- Produces: в `topics.yaml` у модуля необязательное `target: number` (по умолчанию 60); `checkBalance(module, topics, items, target)`.
- Produces: в `tasks.json` у темы поле `doc?: { id: string; anchor: string }` — первый опорный раздел темы; `ModuleInfo.topics[]` в `taskSchema.ts` получает то же необязательное поле.

**Поведение программы:**
- «Прогресс»: у слабой темы рядом с «Тренировать» ссылка «Открыть норму» (ведёт в библиотеку на `doc`); у неготового модуля строка «в работе»; у готового точность. Прогноз по дням: строка «Шанс пройти порог: N%» из `passProbability`, только когда база не пробная и данных хватает.
- Скрытый шаг кейса не показывается при следующем прохождении; если скрыты все шаги, кейса нет в списке.
- В окнах подтверждения фокус встаёт на первую кнопку; `name` и `id` полей ввода берутся из `useId`.
- На экзамене задание на порядок считается отвеченным после первого показа.
- Права в `capabilities/default.json` сужаются до `core:app:allow-version`, `core:event:default`, `updater:allow-check`, `updater:allow-download-and-install`, только если заказчик подтвердил работу обновления и скачивания библиотеки в 0.3.0. Иначе шаг пропускается с записью в журнал.
